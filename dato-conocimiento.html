¿Quién puede saber lo que sabemos de la huerta?

En el proyecto final estamos armando un aparato para la huerta de la escuela. Mide la luz que le llega a un cantero y la humedad de la tierra.

87341925…

Imaginemos que ya está terminado y lo dejamos midiendo un día entero. Vamos a tener cientos de números.

Hoy vemos dos cosas: cómo pasar de esos números a algo que nos sirva para decidir, y de quién son esos datos.

Parte 1 · Teoría

Dato, información y conocimiento

No es lo mismo tener un número que saber algo. Miren cómo cambia en estos tres pasos, con un ejemplo de la huerta:

Dato873Es un número suelto. Si alguien les dice «873», no saben qué es: ¿873 qué? ¿Dónde? ¿Cuándo?
InformaciónA las 14 h, el sensor de luz del cantero del fondo marcó 873.Es el mismo dato, pero ahora sabemos qué se midió, dónde y cuándo. Ya se entiende.
ConocimientoEl cantero del fondo se queda sin sol a las 15 h: ahí no conviene poner tomates.Para llegar acá hay que juntar muchas mediciones, compararlas y sacar una conclusión que nos sirva para decidir algo.

Imaginemos que el aparato va anotando cada medición en una tabla, una fila por vez:

HoraCanteroLuz
14:00del fondo873
14:30del fondo860
15:00del fondo410
15:30del fondo395

Cada fila es información: las columnas le dicen al número cuándo y dónde se midió. Pero el aparato no escribe en ningún lado «a las 15 h el cantero se queda sin sol». Eso lo descubrimos nosotros cuando miramos la tabla y vemos que entre las 14:30 y las 15:00 la luz bajó a menos de la mitad. Ese es el conocimiento.

Ahora ustedes: ¿cada frase es un dato, información o conocimiento?

A las 15:00. Ahí la luz baja de golpe y no vuelve a subir, porque el sol queda tapado por algo, como los árboles o una pared. Todavía es de día, por eso recién llega cerca de 0 a la noche.

A las 11:00 la luz bajó y a las 11:30 volvió a subir. ¿Qué pasó?

Puede ser cualquiera de las tres, y con un solo sensor no hay forma de saberlo. Como la idea es que el aparato mida solo, sin nadie al lado, la solución es tener otro dato para comparar. Si ponemos un segundo sensor en otro cantero y a las 11 también bajó, fue una nube: tapó el sol para toda la huerta. Si bajó solo este, alguien lo tapó o falló algo. Comparando dos datos sabemos algo que con uno no sabíamos.

Parte 3 · En el código

¿Dónde está todo esto en el programa del aparato?

Todo lo que vimos hasta ahora también pasa adentro del código que vamos a cargar en la placa. Veamos tres pedacitos.

1 · El código le pone contexto al dato

El sensor da solo un número, por ejemplo 873. Para que ese número se convierta en una fila de la tabla, el programa escribe tres cosas, una al lado de la otra y separadas por comas: la hora, el cantero y la luz.

Para escribir usa dos instrucciones: Serial.print escribe algo y se queda en el mismo renglón. Serial.println escribe algo y después baja al renglón de abajo.

int luz = analogRead(A1);   // lee la luz y la guarda en la variable luz
Serial.print(hora);         // escribe la hora
Serial.print(",fondo,");    // escribe ,fondo,
Serial.println(luz);        // escribe la luz y baja de renglón

Son las 14, así que la variable hora vale 14, y el sensor lee 873. ¿Qué aparece en la pantalla?

Aparece 14,fondo,873. Cada línea agrega un pedazo al mismo renglón:

14,fondo,873

print(hora) no escribe la palabra «hora»: escribe lo que vale la variable, que es 14. Lo mismo con luz. Así, el 873 suelto (un dato) queda con su hora y su cantero: ya es información.

2 · El conocimiento se vuelve reglas

Imaginemos que, mirando muchos días, aprendimos tres cosas sobre los canteros: con más de 800 de luz hay sol pleno y van bien los tomates; entre 400 y 800 hay media sombra y van bien las lechugas; y con 400 o menos hay demasiada sombra. Ese conocimiento lo podemos escribir en el código, para que el aparato le recomiende qué plantar a cada cantero:

if (luz > 800) {
  Serial.println("sol pleno: tomates");
} else if (luz > 400) {
  Serial.println("media sombra: lechugas");
} else {
  Serial.println("sombra: mejor otro cantero");
}

if es «si», else if es «si no, si…» y else es «si no». El programa revisa las condiciones de arriba para abajo y hace solo la primera que se cumple. Las demás las saltea.

a) El sensor lee 873. ¿Qué escribe?

«sol pleno: tomates». 873 es mayor que 800, así que se cumple la primera condición. 873 también es mayor que 400, pero el programa ya no mira la segunda: hace solo la primera que se cumple.

b) El sensor lee justo 400. ¿Qué escribe?

«sombra: mejor otro cantero». luz > 400 quiere decir «mayor que 400», y 400 no es mayor que 400: es igual. No se cumple ninguna de las dos condiciones, así que hace lo del else. Si quisiéramos que el 400 cuente como media sombra, habría que escribir luz >= 400 («mayor o igual»).

c) Alguien copió el código y dio vuelta el orden de las dos primeras condiciones:

if (luz > 400) {
  Serial.println("media sombra: lechugas");
} else if (luz > 800) {
  Serial.println("sol pleno: tomates");
} else {
  Serial.println("sombra: mejor otro cantero");
}

Ahora el sensor lee 873. ¿Qué escribe?

«media sombra: lechugas», aunque haya sol pleno. 873 es mayor que 400, así que se cumple la primera condición y el programa no sigue mirando. Con este orden, «sol pleno» no aparece nunca: cualquier número mayor que 800 ya es mayor que 400. En una cadena de else if, el orden cambia lo que hace el programa.

3 · Dos sensores para saber más

¿Se acuerdan de la baja de las 11? Con dos sensores, uno en el cantero del fondo y otro en el de adelante, el programa puede distinguir solo una nube de otra cosa. && quiere decir «y»: se tienen que cumplir las dos cosas.

if (luzFondo < 500 && luzAdelante < 500) {
  Serial.println("nube");             // bajaron los dos
} else if (luzFondo < 500) {
  Serial.println("revisar el fondo"); // bajó solo uno
}

A las 11, luzFondo vale 470 y luzAdelante vale 900. ¿Qué escribe?

Escribe «revisar el fondo». Para «nube» tienen que estar los dos por debajo de 500, y el de adelante está en 900. Entonces bajó solo el del fondo: algo lo tapó o falló. El aparato llegó a esa conclusión solo, comparando dos datos.

Parte 4 · Teoría

¿De quién son los datos?

Para sacar conclusiones, primero hay que poder ver los datos. Con los de nuestra huerta es fácil, porque los juntamos nosotros. Pero muchos datos que se juntan en el mundo tienen un dueño, y el dueño decide quién los puede usar. Hay dos formas de manejarlos:

Datos libres (abiertos)
  • Cualquiera los puede ver, bajar y usar.
  • Se pueden copiar, mejorar y volver a compartir.
  • Una licencia lo dice por escrito.
  • Si el que los juntó desaparece, los datos siguen.
Datos privativos
  • Tienen dueño, y el dueño decide quién entra.
  • A veces se ven, pero no se pueden bajar ni copiar.
  • Pueden cobrar por usarlos, o cambiar las reglas.
  • Si el dueño cierra, los datos se van con él.

Pasa lo mismo que con el software libre: que algo sea gratis no quiere decir que sea libre. Una app puede ser gratis y aun así no dejarte bajar ni usar tus propios datos.

Parte 5 · Casos

Siete casos

Los primeros seis pasaron; el último es inventado. Ábranlos de a uno, lean y respondan la pregunta de cada uno.

1

OpenStreetMap y Google Maps

En internet hay dos grandes mapas del mundo. Uno es Google Maps, el que casi todos tienen en el celular: lo hace la empresa Google. El otro es OpenStreetMap: lo hacen voluntarios de todo el mundo, como una Wikipedia de mapas. En mayo, ustedes mapearon la escuela y sus alrededores en OpenStreetMap con el equipo de HOT.

Los datos de OpenStreetMap tienen licencia libre: cualquiera puede bajar todas las calles y usarlas para lo que necesite. Google Maps se ve muy bien, pero sus datos son de Google: se pueden mirar en la app, pero no se pueden bajar ni copiar para hacer otra cosa.

Después de un terremoto, una organización necesita el mapa de calles de un barrio para repartir ayuda, y lo tiene que cargar en sus propios teléfonos. ¿Cuál puede usar sin pedir permiso?

OpenStreetMap. Es justo lo que hace HOT: después de terremotos y huracanes, miles de voluntarios mapean en pocos días y esos datos los usa cualquiera que esté ayudando. Por eso vinieron a la escuela.

Más: hotosm.org

2

El tractor que no te deja arreglarlo

John Deere es la empresa de tractores y máquinas para el campo más grande del mundo. Sus tractores nuevos tienen computadoras adentro, con el programa cerrado. Durante años, los productores de Estados Unidos no podían arreglar su propio tractor: tenían que llamar al servicio técnico de la marca, aunque supieran qué estaba roto. En 2025 el gobierno de Estados Unidos le hizo juicio a la empresa por eso. El reclamo de los productores se llama derecho a reparar.

El productor pagó el tractor. ¿De quién es, entonces?

No hay una sola respuesta, y por eso hubo un juicio. El tractor lo pagó el productor, pero el programa que lo hace funcionar, y los datos que junta del campo, los controla la empresa. Cuando una máquina tiene el software cerrado, el que la compra no puede hacer con ella todo lo que quiere.

Más: la demanda de la FTC (en inglés)

3

Vecinos que miden el aire

En las ciudades grandes, el humo de los autos y de las fábricas ensucia el aire, y respirar ese aire enferma. Pero los medidores oficiales son pocos y caros, así que muchos barrios no saben qué aire respiran.

En 2015, en Stuttgart, una ciudad de Alemania, un grupo de vecinos decidió medirlo por su cuenta. Se armaron un sensor casero (una placa, como la nuestra, y un sensor de polvo), lo pusieron en la ventana y subieron los datos a un mapa abierto. Así nació Sensor.Community. Hoy hay miles de sensores en muchos países, y cualquiera puede ver y bajar los datos.

¿Para qué les sirvió que los datos fueran abiertos?

Como los datos son públicos, un barrio puede mostrar que su aire está más contaminado que el de otro, y cualquiera puede revisar que sea cierto. Se parece a lo que hicimos en mayo con el mapa: medir y mapear sirve para que un problema se vea.

Más: sensor.community

4

Los satélites que ven los incendios

En la cordillera, cada verano hay incendios forestales. Cuanto antes se detecta un foco, más fácil es apagarlo.

La NASA, la agencia espacial de Estados Unidos, tiene satélites que pasan varias veces por día sobre todo el planeta y detectan los lugares donde hay mucho calor, como un fuego. Esos datos los publica en un mapa llamado FIRMS, gratis y abierto, pocas horas después de que pasa el satélite. Los usan brigadistas, investigadores y vecinos de todo el mundo, también acá en la Patagonia.

Empieza un incendio en la cordillera. ¿Por qué sirve que estos datos sean abiertos?

Cuando hay un incendio, cada hora cuenta. Si para ver el mapa hubiera que pagar o pedir permiso, los datos llegarían tarde o no llegarían a los que están cerca del fuego.

Más: el mapa de FIRMS

5

El mapa de los que salen a correr

Strava es una app para registrar cuando salís a correr o a andar en bici: el celular o el reloj va anotando por dónde pasás. En 2017, la empresa publicó un mapa del mundo con todos los recorridos de sus usuarios juntos, para mostrar por dónde corre la gente.

En 2018, un estudiante australiano de 20 años miró ese mapa y vio algo raro: en medio del desierto, en países como Afganistán o Siria, aparecían líneas de gente corriendo en círculos. Eran soldados que salían a correr con su reloj dentro de bases militares secretas. Cada soldado había compartido solo sus vueltas, pero todos juntos mostraban dónde estaban las bases.

¿Qué nos enseña este caso?

Es lo mismo que vimos con la huerta: con muchos datos juntos se llega a un conocimiento. A veces es un conocimiento que nadie quería que se supiera. Por eso, antes de publicar datos, hay que preguntarse qué se puede saber juntándolos.

Más: la nota de la BBC (en inglés)

6

El test de Facebook

En 2014, en Facebook circulaba un test de personalidad, de esos de «¿qué tipo de persona sos?». Para hacerlo, había que darle permiso a la app para ver tu perfil. Lo que casi nadie sabía es que la app también se llevaba datos de todos tus amigos.

Así, una empresa llamada Cambridge Analytica juntó datos de hasta 87 millones de personas y los usó para mandar publicidad política armada a la medida de cada uno, en campañas electorales. Se supo en 2018 y fue un escándalo mundial: Facebook tuvo que dar explicaciones y pagar multas.

Los que hicieron el test, ¿sabían para qué se iban a usar sus datos?

No lo sabían, y sus amigos ni siquiera habían hecho el test. Cuando los datos son de una empresa, el que los generó muchas veces no sabe adónde van ni para qué se usan. En Argentina, la Ley de Protección de Datos Personales dice que cada persona tiene derecho a saber qué datos suyos se guardan y para qué.

Más: la nota de BBC Mundo

7

El sensor que vino de regalo

Este caso no pasó en nuestra escuela, pero es algo que pasa seguido. Imaginemos que una empresa le regala a la escuela un sensor para la huerta. El sensor mide la humedad de la tierra y manda los datos por internet a las computadoras de la empresa. Para verlos hay que entrar a la app de la empresa, porque en la escuela no queda guardado nada.

Durante dos años lo usamos sin problemas. Un día, la empresa decide cerrar la app.

¿Qué le queda a la escuela?

Un sensor que ya no sirve y ningún dato. Compárenlo con el aparato que estamos armando: el código lo tenemos nosotros, Arduino es libre y los datos quedan en una planilla de la escuela. Aunque cierre una empresa, nuestro aparato sigue midiendo y los datos siguen siendo nuestros.
